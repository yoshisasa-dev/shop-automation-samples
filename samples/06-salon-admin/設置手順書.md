# 設置手順書：予約・顧客管理Webアプリ（ヘアサロン ことり・架空のサンプル店）

お店の人がログインして使う管理画面です。お客さんの台帳・来店の記録・予約のカレンダー・今月の数字をひとつにまとめています。
**すべて架空のデータ**です（お客さんのメールは example.com、電話は 090-0000-XXXX）。

- 画面：React ＋ TypeScript（Vite）
- データとログイン：Firebase（Firestore・Authentication）
- 公開：Firebase Hosting（無料の範囲）

## できること
| 画面 | 中身 |
|---|---|
| ログイン | メールとパスワード。店の人として登録されていない人は入れない |
| 今日 | 今日の予約をスタッフ別に。今月（と先月）の来店数・売上・新規の人数 |
| 予約（日） | スタッフ3人の列×30分の行。空いているマスを押すと予約の追加、予約を押すと変更・取り消し |
| 予約（週） | 月曜〜日曜の7日分。日付を押すとその日の表示へ |
| お客さん | 名前・ふりがな・電話で検索（カタカナ・ハイフンなしでも見つかる）。お客さんの追加 |
| お客さんの詳しい画面 | 連絡先・メモの編集、来店の記録の一覧と追加（最終来店日も自動で更新） |

- 同じスタッフで時間が重なる予約は保存できません（「◯◯さんの予約（10:00〜11:00）と重なっています」と出ます）
- 火曜（定休日）は予約できません。閉店（19:00）をこえる予約もできません
- 取り消した予約は消さずに「取り消し」の印を付けます
- 来店の記録は、未来の日付では記録できません（打ちまちがいで最終来店日がおかしくならないように）

## 必要なもの
- Node.js（22.12 以上）と npm
- Java（21 以上。Firebase のエミュレーターを動かすのに使います）

## 自分のパソコンで動かす（練習用のFirebase＝エミュレーター）
本物のFirebaseを使わずに、自分のパソコンの中だけで動かせます。

```bash
cd samples/06-salon-admin
npm ci
cp scripts/demo-user.example.json scripts/demo-user.json   # 見本用のログイン情報（エミュレーター専用）
npm run emulators      # 練習用のFirebaseを起動（このウィンドウは開いたまま）
```

別のウィンドウで：

```bash
cd samples/06-salon-admin
npm run seed           # 見本用のログインユーザーとサンプルデータを入れる（何回でも入れ直せる）
npm run dev:emu        # 画面を起動 → http://localhost:5173
```

ログインには `scripts/demo-user.json` のメールとパスワードを使います（練習用のFirebaseの中だけで使えるものです）。
`scripts/demo-user.json` は `.gitignore` に入れてあり、リポジトリには含めません。

## テスト
```bash
npm test               # 時間・重なり・検索・集計・サンプルデータのテスト（28件）
npm run test:emu       # 練習用のFirebaseで、アクセスの決まりとデータの読み書きのテスト（8件）
npm run build          # 公開用のファイルを作る（dist/ に出ます）
```

`npm run test:emu` は、エミュレーターを自動で起動して、テストが終わると止めます（Java が必要です）。

## 本物のFirebaseに公開する手順
1. Firebase コンソールで新しいプロジェクトを作る（無料の Spark プランのままで動きます）
2. 「Authentication」でメール／パスワードを有効にし、お店の人のユーザーを作る。**「ユーザーアカウントの作成」（新規登録）は止めておく**
3. 「Firestore Database」を作る（場所は asia-northeast1 など、お店に近い地域）
4. 「プロジェクトの設定」→「マイアプリ」でウェブアプリを追加し、表示された値を `.env.example` をまねて `.env.production` に書く（`.env.production` は `.gitignore` に入っていて、リポジトリには含めません）
5. `.firebaserc` のプロジェクト名を、作ったプロジェクトのIDに変える
6. `npx firebase login` で、プロジェクトを作ったGoogleアカウントにログインする
7. `npm run build` → `npx firebase deploy --only hosting,firestore`
8. Firestore に `members/{作ったユーザーのUID}` のドキュメントを手で作る（中身は `name: "店長"` など）。これがないとログインできない
9. 最初のデータ（スタッフ・メニュー）は、`scripts/seed-emulator.ts` をもとに本番用の管理スクリプトを用意して入れる

## 気をつけること
- 重なりのチェックは「保存の直前に、その日の予約を読み直す」方法です。2台の端末でまったく同時に同じ枠を保存すると、まれに両方入ることがあります。同時に使う人が多いお店では、スタッフ・日ごとの「鍵」（トランザクション）を使う方法に変えます
- 今日の画面の「新規の人数」を正しく出すため、来店記録をすべて読み込んでいます。見本の件数（100件ほど）なら軽いですが、何万件にもなるお店では、お客さんに「最初の来店日」を持たせる形に変えます
- 本物の公開では、新規登録を止めておくこと（手順2）と、`members` に入れた人だけが使えるルール（`firestore.rules`）の両方で守ります
